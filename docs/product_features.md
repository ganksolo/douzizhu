# 产品功能说明书 (Product Feature Specification)

**项目名称**: 4-Player Dou Dizhu (四人斗地主)
**当前版本**: Phase 15 (Backend Engine Ready)
**最后更新**: 2025-11-29

## 1. 项目简介
本项目致力于打造一款高品质、沉浸式的四人斗地主游戏。从单机智能对战起步，逐步演进为支持多人实时在线竞技的现代化 Web 游戏平台。项目注重极致的用户体验（流畅动画、逼真音效、智能辅助）以及稳健的技术架构（状态机引擎、数据持久化、防作弊机制）。

---

## 2. 功能模块详解

### 2.1 核心玩法 (Core Gameplay)
> 还原经典，规则严谨，支持四人同台竞技。

*   **标准四人规则** - [完整还原四人斗地主规则，两副牌，四人博弈，地主以一敌三] - [实现阶段: Phase 2, Phase 12]
*   **完整游戏流程** - [包含洗牌、发牌、叫分（抢地主）、出牌、结算等完整环节] - [实现阶段: Phase 4]
*   **牌型识别与比较** - [自动识别单张、对子、三带、顺子、炸弹、火箭等所有合法牌型，并判断大小] - [实现阶段: Phase 2, Phase 12]
*   **积分结算系统** - [基于底分、倍数（炸弹/火箭翻倍）、春天/反春天等规则自动计算每局输赢分数] - [实现阶段: Phase 10]
*   **四人布局适配** - [专门设计的四人牌桌布局，清晰展示各方手牌数、出牌区和身份标识] - [实现阶段: Fix 1]

### 2.2 用户体验与交互 (User Experience & Interface)
> 打造丝滑、直观、悦耳的操作体验。

*   **智能选牌操作** - [支持点击选牌和“拖拽框选”两种模式，操作顺滑跟手] - [实现阶段: Phase 3, Phase 8]
*   **智能提示系统** - [当玩家不知道出什么牌时，系统能智能推荐最优牌型（优先推荐顺子、连对等长牌）] - [实现阶段: Phase 8, Fix 5]
*   **沉浸式动画特效** - [发牌动画、出牌飞行轨迹、炸弹震屏、飞机飞过、胜利/失败结算动画] - [实现阶段: Phase 6, Phase 7]
*   **音效与背景音乐** - [逼真的发牌声、出牌声、背景音乐，支持静音开关和自动播放策略] - [实现阶段: Phase 7, Fix 3]
*   **个性化主题** - [提供“经典绿”、“科技蓝”、“木纹风”等多套皮肤，玩家可自由切换] - [实现阶段: Phase 8]
*   **即时反馈机制** - [使用 Toast 轻提示和美观的弹窗替代原生弹框，信息展示更友好] - [实现阶段: Fix 2]
*   **手牌交互优化** - [出牌后自动整理手牌，点击空白处取消选择，悬停高亮等细节打磨] - [实现阶段: Fix 4]

### 2.3 智能对手 (Artificial Intelligence)
> 即使单人游玩，也能享受高质量的对局挑战。

*   **单机对战模式** - [在没有网络或凑不齐人时，由 AI 补位进行对战] - [实现阶段: Phase 5]
*   **高级策略 AI** - [AI 懂得保留炸弹、配合队友（农民互助）、残局阶段激进出牌等高级战术] - [实现阶段: Phase 9]
*   **AI 思考可视化** - [提供调试模式，可查看 AI 的手牌评分和出牌决策逻辑（仅供开发/学习使用）] - [实现阶段: Phase 9]
*   **自动托管** - [玩家可开启托管模式，由 AI 代替自己出牌] - [实现阶段: Phase 9]

### 2.4 在线对战 (Online Multiplayer)
> 突破单机限制，实现真实玩家间的实时博弈。

*   **实时联网对战** - [基于 WebSocket 技术，实现毫秒级延迟的多人实时同步] - [实现阶段: Phase 15]
*   **房间系统** - [支持玩家创建房间、加入房间，与好友同桌竞技] - [实现阶段: Phase 15]
*   **防作弊机制 (战争迷雾)** - [服务端严格控制数据发送，玩家只能收到自己的手牌数据，杜绝抓包看牌作弊] - [实现阶段: Phase 15]
*   **断线重连与状态恢复** - [游戏状态实时保存至服务器（Redis），意外刷新或断线后可无缝恢复当前对局] - [实现阶段: Phase 15]

### 2.5 技术基建 (Technical Infrastructure)
> 稳健的底层架构,保障游戏的高性能与可扩展性。

*   **全栈单体仓库 (Monorepo)** - [统一管理前端与后端代码，复用核心游戏逻辑，提升开发效率] - [实现阶段: Phase 13]
*   **高性能后端架构** - [采用 NestJS + Redis + MySQL 架构，支持高并发和数据持久化] - [实现阶段: Phase 14]
*   **状态机引擎** - [前后端均采用有限状态机 (FSM) 管理游戏流程，确保逻辑严密，杜绝状态错乱] - [实现阶段: Phase 11, Phase 15]
*   **事件驱动架构** - [通过事件总线 (Event Bus) 实现组件解耦，UI 和逻辑层完全分离，易于维护和扩展] - [实现阶段: Phase 11]
*   **纯函数式规则引擎 (4人场)** - [后端实现双副牌（108张）规则引擎，支持天王炸、炸弹分级（4-8张）、飞机等复杂牌型识别与比较，覆盖率 100%] - [实现阶段: Phase 16]
*   **完整测试覆盖** - [规则引擎包含47+个前端单元测试，后端核心规则通过 Jest 验证] - [实现阶段: Phase 12 & 16]

## 3. 演进日志 (Changelog Summary)

*   **Phase 1 - 4 (原型构建)**: 完成了游戏的基础骨架，实现了发牌、出牌、胜负判定等核心单机玩法。
*   **Phase 5 - 9 (体验升级)**: 引入了 AI 对手，大幅优化了 UI/UX，增加了动画、音效、拖拽选牌和智能提示，使游戏具备了商业级产品的雏形。
*   **Phase 10 - 12 (架构重构)**: 补全了积分系统，重构了底层代码架构（状态机、事件总线、规则引擎），实现了前后端逻辑分离，为后续扩展打下坚实基础。所有核心规则通过单元测试验证。
*   **Phase 13 (工程化)**: 项目重构为 Monorepo 架构，前后端代码物理隔离但逻辑复用，为全栈开发做好准备。
*   **Phase 14 - 15 (联机转型)**: 从纯前端单机游戏转型为全栈联网游戏。搭建了后端服务，实现了多人实时同步、数据持久化和防作弊传输，完成了核心网络对战引擎。
*   **Phase 16 (规则引擎)**: 后端移植并增强了核心规则引擎，支持四人场双副牌规则（108张），实现了炸弹分级、火箭判定及复杂牌型的校验与比较，并通过了全面的单元测试与边界检查。
*   **Phase 17.1 (AI 核心)**: 实现了后端 AI 的基础架构，包括启发式手牌评估器 (HeuristicEvaluator) 和动态策略模型 (StrategyModel)，支持根据手牌质量和局势自动切换“保守/均衡/激进”策略。
*   **Phase 17.2 (AI 决策)**: 重构了决策引擎 (DecisionEngine)，引入了完整的决策流水线 (Detection -> Filter -> Simulation -> Strategy)。实现了基于 `AIExplain` 的可解释性调试接口，并定义了明确的战术优先级（如晚期激进、早期控雷）。
*   **Phase 17.3 (AI 集成)**: 完成了 AI 服务 (AIService) 与游戏主循环 (PlayingState) 的深度集成。实现了自动托管机制，AI 能够在规定时间内（1.5秒思考时间）自动接管掉线或托管玩家的操作，保证游戏流畅进行。
*   **Phase 18.1 (动作管线)**: 建立了安全可靠的动作处理管线 (ActionPipeline)。引入了 `InputNormalizer` 对客户端输入进行身份绑定与格式清洗，防御伪造 ID 和恶意 Payload 攻击，确保后端逻辑接收到的均为可信数据。
*   **Phase 18.2 (回合管理)**: 实现了 `TurnManager` 和策略模式的动作处理器 (`PlayActionHandler`, `PassActionHandler`)。支持标准的逆时针轮转、连续跳过清空（Free Turn）逻辑以及游戏结束判定，确保游戏流转符合四人斗地主规则。
*   **Phase 18.3 (集成与持久化)**: 完成了动作管线的完整集成。实现了 Redis 分布式锁（SET NX PX）防止并发冲突、原子写入保证数据一致性、自动回滚策略（失败时 Redis 保留旧状态），并与 GameGateway 集成实现状态广播。确保了多人在线游戏的高可用性和数据安全性。
